# 22 - 视觉系统（terminal / paper）

> 2026-11-13 起生效。替换掉早期 shadcn 默认外观（柔阴影、12px 圆角、蓝紫强调色）。

## 1. 定位

**深色交易终端（Bloomberg 血统）+ 工业仪器的纪律**，浅色配套叫 **paper**。

一句话判据：界面要像一个**仪器**，不是一个**应用**。仪器的特征是数字对得齐、分区靠线不靠阴影、强调色有语义、装饰为零。所以明确不做：霓虹渐变、发光、玻璃拟态、大圆角、药丸徽章。

这条判据是可执行的：任何"加一点效果会更好看"的提议，先回答"它让数字更容易读吗"，答不上来就不加。

## 2. 令牌层

所有视觉参数只存在于 `src/styles/globals.css`。组件只消费令牌，不写字面色值。

### 2.1 表面阶梯

```
--s-base     页面底色
--s-card     卡片（比 base 高一档）
--s-hover    悬停（浅色变暗、深色变亮）
--s-float    浮层（弹窗、下拉）
--s-sunken   凹陷（输入框底、进度槽）
--s-ink      正文墨色
--s-muted    次要文字
--hue / --chroma   氛围参数
```

表面统一是 `oklch(lightness chroma hue)`，**亮度单独成阶、色相色度抽出来做参数**。这样 6 个氛围主题（warm / cool / ocean / forest / midnight / rose）各自只有两行覆盖，不需要维护 6 份完整调色板。新增氛围主题的成本是两行。

**`--s-hover` 与 `--s-float` 必须分开。** 它们看起来是同一件事（"比卡片亮一点"），实际在两个模式下漂移方向相反：浅色里 hover 要变暗、浮层要变亮；深色里两者都变亮。合成一个 `--s-raised` 会让浅色的下拉菜单看起来"凹进去"。

### 2.2 层级不用阴影

```css
--shadow-*: none;  /* 全部 */
--radius-sm: 4px;  /* 徽章、标签页、骨架 */
--radius-md: 6px;  /* 按钮、输入框、下拉 */
--radius-lg: 8px;  /* 弹窗 */
--radius-xl: 10px; /* 卡片 */
```

分区只靠 **1px 发丝线**（`--color-border`）与表面亮度差。收益不只是好看：阴影在深色底上几乎不可见却会拖慢滚动，而发丝线在两种模式下都成立。

圆角是**收着**，不是「没有」。曾经把控件压到 2px，32px 高的按钮看起来像被削掉一角，整屏失去「这里可以点」的暗示——终端感来自等宽数字、发丝线和零阴影，不来自直角。控制在控件 6px / 卡片 10px：卡片比控件大一档，嵌套关系不用阴影也读得出来。`rounded-full` 只留给开关和圆点，不做药丸徽章。

浅色态的发丝线 alpha 是 `0.15`（不是 0.13）。没有阴影之后，这条线是卡片与页面之间**唯一**的分隔，0.13 在亮屏上会消失。

### 2.3 语义色

| 令牌                | 含义               | 使用位置                     |
| :------------------ | :----------------- | :--------------------------- |
| `--color-signal`    | 唯一的强调色（琥珀） | 关键数字、当前项、超支、待办 |
| `--color-income`    | 收入 / 正方向      | 收入金额、正结余             |
| `--color-expense`   | 支出 / 负方向      | 支出金额、负结余、超支       |
| `--color-info`      | 信息               | 链接、时间序列、资产         |
| `--color-primary`   | 墨色（近白/近黑）  | 主按钮底                     |

三条硬规则：

1. **强调色只有一支**，且只出现在上述位置。满屏琥珀按钮会让强调失效。
2. **语义色不跟随强调色**。预设换成冰蓝或墨戳，收支仍然是红绿——`--income` / `--expense` 独立定义。
3. **禁止 Tailwind 调色板类**（`text-red-600` / `bg-emerald-500`）。一律用 `text-income` / `text-expense` / `text-signal` / `text-info`。已全量替换 22 个文件 73 处，新增代码照此办理。

`--color-primary` 不是强调色，它是墨色。这是本系统最容易误用的一个令牌。

### 2.4 预设：四种，不是 126 种

```
[data-preset="terminal"]       hue 250 / tint x1     signal 65   琥珀   默认
[data-preset="terminal-cool"]  hue 234 / tint x1.15  signal 205  冰蓝
[data-preset="paper"]          hue 78  / tint x1.5   signal 55   墨戳
[data-preset="contrast"]       hue 250 / tint x0     signal 65   + 加粗发丝线
```

一个预设只设四样：表面色相、**色度倍数**、信号三元组，以及（只有 contrast）发丝线权重。所有**亮度**仍然来自上面的表面阶梯，所以预设不可能把界面做成不可读——最坏情况是色相选得不对，不是白字白底。

**色度必须是倍数，不能是绝对值。** 浅色态 `--chroma-base: 0.006`、深色态 `0.019`：预设若直接写 `--chroma`，同一个值要么让深色发灰、要么让浅色发蓝。所以 `:root` 里是 `--chroma: calc(var(--chroma-base) * var(--chroma-scale))`，预设只给倍数。

**为什么用 `data-preset` 而不是 class**：`paper` / `contrast` 都是可能与工具类撞名的词；属性选择器与 `.dark` 同权重，靠**源码顺序**（预设块必须在模式块之后）决定胜负，这条顺序不能调。

设置页的缩略图是**真的把预设套在子树上**（`data-preset` + `data-mode` + `.preset-preview`），不是写死几个 hex。代价是 `.preset-preview` 必须重新声明缩略图用到的几个令牌：`var()` 在**声明处**解析，只改子树的 `--hue` 不会让 `:root` 上已经算好的 `--color-*` 跟着变。

旧存储（`glimmerx:color` 的 18 个值、`glimmerx:atmosphere` 的 7 个值）在首次启动时映射成预设并**删除**——留着的话，改一次映射规则就会把用户后来选的主题顶掉。

## 3. 字体

```
--font-mono: "JetBrains Mono", ui-monospace, ...（不含任何 CJK 字体）
--font-sans: system-ui, "PingFang SC", "Microsoft YaHei", ...
```

- **数字与日期走 mono，中文走 sans**。汉字在等宽字体里会撑爆列宽，所以 `--font-mono` 刻意不列 CJK 家族，让汉字自然回落到系统字体。
- 字体**本地打包**（`src/assets/fonts/`，latin 子集 400/500 共 42 KB，含 OFL 授权）。Tauri 离线运行，CDN 不可用，CSP 也不该为字体开口子。
- `html` 上挂 `font-feature-settings: "tnum" 1, "lnum" 1`。金额列不需要逐个写 `tabular-nums`。
- **中文没有 600/700 字重**。`font-bold` 会触发合成粗体，糊成一团。层级只靠字号与色阶，最强只到 `font-medium`。

### 3.1 字阶

```
11 / 13 / 15 / 20   （--text-xs / sm / base / xl，覆盖了 Tailwind 默认的 12/14/16）
```

比 Tailwind 默认小一档，换来一屏多一行。数字按位置分三级：

| 位置                     | 尺寸 | 类                                |
| :----------------------- | :--- | :-------------------------------- |
| 页面级汇总（状态条、报表头） | 20px | `text-xl font-mono font-medium`   |
| 卡片内关键数字           | 15px | `text-base font-mono font-medium` |
| 表格与列表               | 13px | `text-sm font-mono`               |

## 4. 图表色板

```css
--chart-1 … --chart-8   /* 分类序列，深/浅各一套 */
--chart-grid            /* 网格线，单独定义 */
```

- 顺序按"被读到的频率"排，不按光谱：前四色承担大多数图表，灰阶留给尾部，第十个切片不需要第十种色相。
- chroma 压在 0.09–0.16。高饱和分类色会让六个扇区看起来像荧光笔。
- **`--chart-grid` 独立于 `--color-border`**：边框用发丝线够了，网格线要再淡一档才不抢数据。

色值由 `src/utils/chartColors.ts::useChartColors()` 读取，**不是直接写 CSS**。原因是 ECharts 把图画进 `<canvas>`，canvas 既不解析 `var()` 也不认 CSS 类。所以颜色从 computed style 读出后喂给 JS，并在 `effectiveTheme` / `preset` 变化时重算。

## 5. 密度

- 4px 网格；列表行高 36px（`py-2` + 13px 行高）。
- 卡片内距 12/16（原 24 偏松）；表格单元格 `px-3 py-2`。
- 侧栏 208px、页头 44px。
- 动效 120ms `cubic-bezier(.2,0,0,1)`，无回弹；`prefers-reduced-motion` 全局降级。
- 焦点环 `ring-1`（实线），不是 3px 半透明光晕——仪器只给一次明确的注视点。

## 6. 首页结构

```
状态条：净资产 · 本月收入 · 本月支出 · 本月结余   （无卡片外框，发丝线分隔）
┌──────────────┬──────────────────────┬────────────┐
│ 月度收支图    │ 最近交易（表格）      │ 预算        │
│ （吃掉余高）  │ 吸顶表头 + 面板内滚动 │ 账户余额    │
│ 支出按分类 300│                      │ Top 支出    │
└──────────────┴──────────────────────┴────────────┘
```

**三栏同高靠视口，不靠 calc。** 页面根 `h-full`（main 的高度是确定的），grid `flex-1 min-h-0`，于是那一行的高度 = 剩下的视口高度，三栏被拉到同一底边；每张卡片再 `flex-1` 分配，卡片内部滚动。`min-h-full` 不行：高度回落到 `auto`，`flex-1` 就失去基准，卡片缩回内容高度——这才是之前"拉伸无效"的真正原因。

**哪张卡吃掉余高是有讲究的。** 时间序列越高越好，所以月度图 `flex-1`；环形图不吃高度（半径是定值，变高只是留白），固定 300px。右栏三张列表各分 1/3，各自滚动。

**为什么是状态条而不是卡片**：此前是 4 张汇总卡 + 3 张健康卡，共 7 个面板读 7 个数字，每个数字还各在自己的基线上，比较时必须上下移眼。状态条把四个数字放上同一条线、同一列宽、同一字体——这是"一眼看出"成立的前提。

**为什么交易用表格**：每行一张卡时，八条交易填满整栏且行与行之间没有任何东西对齐。表格同样面积放三倍条目，并且金额成了**一列**，眼睛比较的是量级而不是重新找数字。

**金额符号按现金流**：`displayAmount` 是借方合计、恒为正，用它着色会把每一笔支出画成收入。列表项因此带 `flow_amount`（只汇总资产/负债侧）：支出为负、收入为正、自有账户互转为 0（中性显示，因为钱没离开这个家）。

## 7. 已知取舍

- **面板内滚动是刻意的不便**。三栏同高意味着矮窗口里列表在栏内滚，而不是整页往下长。仪表盘这样做是对的（一眼看全），但窗口高度小于约 700px 时右栏三块会挤，只能滚。报告页不走这套，仍然是整页滚动。
- **浅色态是"冷纸"不是反色**。`--s-base` 带一点蓝（hue 250, chroma 0.006），配白色卡片。深色态不是它的反转，两套是分别调的。
- **`¥-50.00` 已废弃**，负数写作 `-¥50.00`（符号在货币符号前）。`formatAmount` 已改，测试锁住。
- **打印不是导出 PDF**。仓库里没有 jsPDF / html2canvas，`@media print` 是给 WebView2 的 Ctrl+P 用的：翻成纸张令牌（纯白底、`--line` 0.6）、隐藏侧栏与按钮、卡片 `break-inside: avoid`、表头 `table-header-group`、图表给定 60mm 高度（`auto` 容器会让 canvas 印成空白，`EChart` 在 `beforeprint` 时按纸张尺寸重绘）。真要"导出 PDF"按钮，得另做一条链路。
- **`--radius` 无前缀别名只放在 `:root`**。Tailwind 会裁掉 `@theme` 里没被工具类引用的变量，而 sonner 的 toast 用 `var(--radius)` 取值——写进 `@theme` 会在某次重构后突然变 0。
