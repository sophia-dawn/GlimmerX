# 24 · 报表重构：六张报表，一次筛选

> 决策日期：2026-11-14。旧版 9 张报表 → 6 张，图表库 Recharts → ECharts 6。

## 问题

旧的报表页有 9 张报表，但只有 5 个问题被回答。四个报表用四种框架回答同一件事
（这段时间钱怎么动的）：

| 旧报表 | 它能回答的 | 它答不了 |
|---|---|---|
| 标准财务报表 | 期间收入/支出 + 环比 | 看不出走势形状 |
| 收支趋势图 | 按粒度画出收支曲线 | 没有环比、没有 KPI |
| 月度对比报告 | 手工挑两个月对比 | 只能两两比，不能比"上个等长周期" |
| 年度汇总报告 | 12 个月 + Top 5 分类 | 周期被写死成自然年 |

想判断"十月是不是比九月差"要开两张报表，再心算。账户维度同理：
`账户交易报告` 与 `账户余额趋势` 各有自己的账户选择器，要对比得选两次账户、
祈祷两边的时间范围一致。所以问题不是"报表太多"，是**报表按实现切的，不是按问题切的**。

另外每张报表都自己复制一份筛选条（共 4 份 `ReportFilterBar` 调用 + 7 套自制日期控件），
筛选状态各自 `useState`：切报表时区间静默重置，页头显示的东西和正文不是一个东西。
`onExport` 是空壳，`REPORT_GROUP_LABELS` 从没被渲染过，`html2canvas` / `jspdf`
装了但没有任何调用点。

## 现在

一张报表回答一个问题，顺序按人读自己账本的顺序：

| 报表 | 问题 | 组件 |
|---|---|---|
| 现金流 | 这段时间进来多少、出去多少、留下多少 | `CashflowReport` |
| 分类构成 | 钱花在哪些类目上 | `CategoryBreakdownReport` |
| 净资产归因 | 净资产变了多少，是哪些账户变的 | `NetWorthAttributionReport` |
| 资产负债表 | 此刻我拥有什么、欠什么 | `BalanceSheetReport` |
| 账户明细 | 某一个账户这段都发生了什么 | `AccountDetailReport` |
| 预算执行 | 计划与实际差多远 | `BudgetExecutionReport` |

审计报告不在报表页了。它回答的是"账本自身是否自洽"（分录是否平衡、有没有未分类），
不是"钱怎么动的"，所以移到 **设置 → 数据体检**，与备份、密码放在一起。

### 一次筛选

时间范围是四张报表共用的一个轴，因此上提到页面、序列化进 URL：

```
/reports?r=cashflow&p=last6Months&g=monthly
/reports?r=accounts&a=<accountId>&p=last12Months
```

只写非默认值，所以第一次进来是干净的 `/reports`。代价是每个报表的控件不一样
（区间 / 快照日 / 月份 / 粒度），收益是返回键可用、报表可分享，
而且不可能出现"页头说近 6 个月、正文算本月"。

报表页布局：左栏目录（6 条，当前项用信号色竖条标记，不用药丸），右栏一张报表。
下拉框藏起整个目录，让人一次只能发现一张报表。

## 图表：Recharts → ECharts 6

换库不是因为旧图画不出来，是因为**该用的能力一个都没用**：旧代码只用了
Recharts 最基础的 `Line`/`Bar`/`Pie`，而工具提示只写了 `formatter`，
没有 `ReferenceLine`、没有 `Brush`、没有标注。Recharts 3.8 其实已经导出这些，
只是没人接。换 ECharts 真正的理由有三条：

1. **一处统一样式层**。`utils/chartTheme.ts` 提供轴、网格、tooltip、图例，
   八张图共用，不再各写各的（旧代码里 `stroke="#16a34a"` 这种硬编码还在）。
2. **画布 + `setOption` 的过程式接口**适合"数据变了就整体重画"，
   而 React 声明式组合在 8 张图 × 4 种序列上产生的是一堆props。
3. 标签排版、`axisLabel.overflow` 截断、legend 滚动这些细节开箱可用，
   不必自己算。

**按需注册**：`components/charts/echarts.ts` 只 `use()` 了 3 种图 + 4 个组件 + canvas
渲染器。整体 `import * as echarts` 会多背 map/geo/dataZoom 一堆用不到的东西，
而这个包是要塞进 Tauri 二进制、永远不上 CDN 的。

**没做的事**：没上 dataZoom / 地图 / K 线 / 桑基。当前数据模型没有
`categories.parent_id`（桑基要层级）、没有 `recurring` 标记（周期支出报表要它），
硬画就是编数据。等 schema 有了再说。

`EChart` 三个必要细节：容器高度为 0 时延迟 init（flex 子项首帧没高度）、
`setOption(..., { notMerge: true })`（区间变短时旧序列会残留）、
`beforeprint` 按纸张尺寸重绘（canvas 是位图，不会自己缩放）。

## 新增的两张报表：零新增 IPC

两张新报表都没有加后端查询，因为需要的数据已经在既有聚合里：

- **净资产归因**：`report_standard` 的 `accountChanges` 同时给出每个账户
  「期初余额」与「期末余额」，两列相减即该账户的变动，加总恰好等于净资产变动。
  这不是估算：`postings` 恒平衡，账户互转在两侧符号相反相互抵消，
  只有来自收入/费用的分录会留在净资产上。所以"部分之和 = 整体"是结构保证，
  不是一个残差项。图表直接用这两列，不存在和曲线对不上的可能。
- **预算执行**：`budget_list_statuses(year, month)` 本来就返回 `amount`（预算）
  与 `spent`（实际），报表只是把它画成"轨道 + 进度条"。

口径必须写明（`reports.scope.*` 每张报表标题下的一行）：**`budgets` 表没有历史快照**，
所以回看旧月份时，实际支出是真的，预算目标却可能是后来改过的版本。
这条写在正文里而不是藏在脚注里，否则那个百分比会被当成事实。

## 打印

`@media print` 里 `.echart` 强制 `60mm` 高度（`auto` 高度会让画布印成空白），
`EChart` 在 `beforeprint` 时重绘到纸张宽度。左栏目录与筛选条 `data-print="hide"`，
报表正文 `data-print="page"` 释放滚动高度。
