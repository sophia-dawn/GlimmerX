## 1. 调研：四条流派，以及它们各自的适用边界

### 1.1 金融终端派 —— 密度即信任

**Bloomberg Terminal** 是这一派的源头。它的美学不是设计师定的，是硬件约束与实时数据流逼出来的：4–9 个面板同屏、11–14px 等宽字、20–24px 行高、`#2A3050` 发丝线、零圆角零阴影、琥珀主数据、红绿只表示涨跌、单元格 tick 时 50–80ms 闪一下。

最值得偷的不是颜色，是两条判断：

- **「密度是透明度」**：专业用户认为「一次只给我看一点」= 你在藏东西。全部摊开反而是信任信号（[Curio: 彭博终端绿屏](https://designbycurio.com/zh/learn/bloomberg-terminal-green)）。
- **「这套语言是需求生成的，不是风格选择的」**：一旦内容配不上密度（演示数据、营销页），它立刻穿帮成戏服（[Curio: 彭博终端琥珀](https://designbycurio.com/zh/learn/bloomberg-terminal-amber)）。

**对我们的边界**：我们不是交易台，用户是一个人、一天记几笔，不需要 40 行表格、不需要命令行导航、不需要 0 圆角（上一轮已证明 2px 圆角被用户判为「圆角弄没了」）。**可以拿的是**：等宽 tabular 数字、发丝线、一次色彩事件、状态用小字而非整句、密度胜任时不要藏东西。

### 1.2 现代工具派 —— 深度来自亮度阶梯，不是阴影

Linear / Vercel / Raycast / Arc 这一派的共识，[一篇拆得很清楚的分析](https://studiomaydit.com/blog/linear-vercel-raycast-aesthetic) 说：值得抄的不是深色和渐变，是**「清晰 > 装饰、克制即自信、字体先行、单色底 + 一支强调色、动效只在引导视线时出现」**；只抄表面会变成「穿着别人身份的戏服」。

具体到实现层级（[Dark Mode Done Right, 2026](https://www.colormixed.com/fashion/black-in-web-design-dark-mode-done-right-in-2026)）：

```
Surface 0  #0F0F0F   app background
Surface 1  #1C1C1E   cards / nav
Surface 2  #252529   elevated cards / sidebars
Surface 3  #303036   hover / active
Surface 4  #38383F   modals
border     #2A2A2A–#3A3A3A（不是纯黑）
```

「层级通过**明度差**传达，而不是靠边框或阴影」——这一句直接支持我们的 `--s-base/--s-card/--s-hover/--s-float` 阶梯，也说明上一轮把阴影全部设 `none` 是对的。

Raycast 的「**一次色彩预算**」更极端：整页只允许一次饱和色事件（一条红色渐变带），其余全部单色；[一份开发者工具辨识度研究](https://github.com/bihanikeshav/fixmyslop/blob/main/docs/design-research/distinctiveness/dev-tools.md) 把它总结为「像奢侈品预算 logo 一样预算颜色」。我们已有的「琥珀只用在关键数字 / 当前项 / 超支 / 待办」正是这条规则。

同一份研究也指出：**「近黑 + 紫色渐变球 + Inter + bento 网格」到 2024 年已经变成新的通用模板**（被称为 "Linear look" / "anonymous SaaS soup"）。这解释了上一轮 B 稿「数据场」为什么观感像 AI 产品落地页——它不是不好看，是**没有身份**。

### 1.3 空间材质派 —— 立体感的物理定义

Apple 在 [WWDC23《Design for spatial user interfaces》](https://developer.apple.com/videos/play/wwdc2023/10076/?time=415) 里把「深度」讲得非常具体：

- 图标由最多三层平面构成，系统自动加 **specular highlights + shadows** 来「强化层间深度」；
- 玻璃材质让环境光透过，同时用高光和阴影标明它在空间里的**位置与尺度**；
- 前景元素「应投下细微阴影，并在**上缘**呈现轻微镜面高光」；
- 用更亮/更厚的材质给前景，更暗/更薄的给背景；
- 文字靠 vibrancy 保住可读性。

Microsoft [Fluent 材质规范](https://learn.microsoft.com/zh-hk/windows/apps/design/signature-experiences/materials) 补上了边界条件，这条对我们最关键：

> **Acrylic（半透明模糊）只用于临时性表面**——飞出窗口、内容菜单、轻量关闭的浮层；**Mica**（不透明、只从桌面壁纸取一点色）用于窗口基础层。并明确警告「不要把多块亚克力边对边叠放」，否则产生分心的接缝。

**结论**：内容面板必须**不透明**，玻璃只给浮层。上一轮 B 稿把整屏面板做成 `backdrop-filter` 玻璃，正好踩了这条；而且它把背景色染进交易表，压低了数字对比度。

Fluent 的阴影还拆成「关键阴影（定义边缘）」+「环境阴影（暗示距离）」，模糊半径与 Z 高度绑定。换成 CSS 就是**紧贴的 1px 接触阴影 + 上缘 1px 高光**，而不是 `0 20px 50px` 那种糊成一片的柔光——这和我上一轮给出的「上亮 / 下暗 / 紧贴投影」是同一件事，只是这次有物理依据。

### 1.4 数据墨水派 —— 对「科技背景」最有力的反对票

[Tufte 的 data-ink ratio](https://infovis-wiki.net/wiki/Data-Ink_Ratio)（1983）：**墨水中承载数据的比例越高越好，「擦掉它是否会丢信息」是唯一检验**。网格线、边框、背景填充、装饰阴影、3D 效果，全部属于该删的非数据墨水。Bloomberg 配方里也明确写着「装饰性渐变不是 data-ink」。

这一派等于直接否决了「为了科技感铺一层网格背景」。但它同时给了出路：[一份实务总结](https://usefuldatatips.com/tips/visualization/data-ink-ratio) 说得很清楚——**浅参考线如果帮助读数就保留，「编码了类别的颜色」是数据墨水，不是装饰**。

**这就是本方案的核心转折**：

> 不做「装饰性背景」，做**「有刻度的背景」**。
> 网格不是壁纸，它是时间轴：横线对齐金额刻度，竖线对齐周；背景里每一格的亮度 = 当日的账目活动。
> 这样它擦不掉——擦掉就丢了「哪几天忙、哪几天静」，从非数据墨水变成数据墨水。

### 1.5 信息架构派 —— 我们最缺的一块

[Grafana / 可观测性仪表盘的三层结构](https://plumephp.com/observability-dashboard-design-ux)：

```
结论层（顶部 1/4）  大数字 + 阈值色，不用读图就能判断
趋势层（中部 1/2）  统一时间范围的时间序列，异常点标注
分解层（底部 1/4）  表格 / Top-N / 热力图，从「哪里不对」到「哪个对象不对」
```

并给了三条我们正好违反的规矩：**重要信息放左上**、**同层同大小不同层用尺寸区分**、**20 个同尺寸小面板平铺 = 没有层级**。

[Stripe 仪表盘](https://mythex.ai/zh-cn/guides/dashboard-design-examples) 还多一层很值得抄的：除了「我们做得怎么样？」，还要有「**什么需要我注意？**」（未处理的争议）。

**映射到我们的业务**——这是本次重构最实质的一处，比任何视觉效果都重要：

| 通用       | GlimmerX                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 结论层     | 净资产（唯一主读数）+ 资产 / 负债 / 本月结余                           |
| 需要我注意 | **未对账分录、超预算分类、未分类交易**（复式记账里真正会出错的三件事） |
| 趋势层     | 现金流、支出结构、90 日净值曲线                                        |
| 分解层     | 最近交易、账户余额、Top 支出                                           |

「待办」不是装饰，它直接来自 `postings.cleared` / `reconcile_id` / `categories.account_id` 这三个已有字段——**别的产品做不出这一层，因为它不懂复式记账**。这才叫有身份的科技感。

### 1.6 来源可信度说明

上面的**一手规范**（Apple WWDC、Microsoft Learn、Tufte 原文）是稳定依据；**二手趋势评论**（2026 深色模式长文、AdminLTE 模板榜、站酷 / DevDojo 拆解）只用来判断「什么已经烂大街」，不当作规范引用。特别地，「Cobalt / Fintora / 金融交易大屏」这类案例的共性是：近黑底 + 细网格 + 星点 + 一支荧光色 + 玻璃卡——**恰好就是上一轮 B 稿**，也恰好是 2024 年后最容易被认成「通用 AI 产品」的组合。

## 2. UI 审查报告：现有首页（skill Audit Protocol，6 维）

| 维度           | 现状                                                              | 判定                                                                       |
| -------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1 视觉层级     | 状态条四项等权 20px，三栏卡片等权；全站最大字号 20px              | **不合格**。没有焦点，违反 Grafana 三层结构；没有「需要我注意」层          |
| 2 色彩系统     | 语义色独立、单支琥珀、`#7E8B9C` 实测 5.46:1、`#5B6675` 只给非文字 | **良好**，是既有资产，不要动                                               |
| 3 排版质量     | 11/13/15/20 字阶、数字 mono、中文刻意不进 mono                    | **良好但缺 display 层**。缺一个 40–48px 的主读数                           |
| 4 间距与对齐   | 8pt 为主；状态条内距 12、卡片 14 不统一                           | **小问题**，统一到 4/8/12/16/24                                            |
| 5 组件一致性   | `Card` 只有一种表面；hover / active / focus 散落各组件            | **不合格**。缺 `raise / well / float` 三态与统一上缘高光                   |
| 6 现代感与审美 | 零阴影 + 发丝线 + 参数化表面阶梯，克制且系统                      | **良好**；但表面全平、背景是纯色，缺少 specular 与尺度参照，所以「不立体」 |

**核心问题（按优先级）**

1. **四个数字一样大，没有主读数** → 建立 46px 净资产读数 + 90 日曲线，其余降为 12px 次级。
2. **没有「待办」层** → 加 Attention Bar，直接复用对账 / 预算字段。
3. **背景是纯色** → 换成有刻度的背景（网格 = 周/金额刻度，格亮度 = 当日活动）。
4. **表面只有一种** → `Card` 分 `raise / well / float`；统一左上 45° 光源；玻璃只给浮层。
5. **动效与 focus 不系统** → 只保留一处呼吸（实时点）+ tick 闪；其余 120ms 无回弹。

## 3. 设计 DNA

**名称：`Calibrated Instrument` / 刻度仪器**（不是赛博、不是 AI 玻璃、不是样板间）

| 项       | 决策                                                                         | 依据               |
| -------- | ---------------------------------------------------------------------------- | ------------------ |
| 一句话   | 一块被使用中的仪器：底板有刻度，面板有厚度，浮层才是玻璃                     | 1.1 + 1.3 + 1.4    |
| 信息架构 | 结论 → 待办 → 趋势 → 分解，四层尺寸递减                                      | 1.5                |
| 背景     | **数据即背景**：32px 校准网格（横=金额刻度、竖=周）+ 90 日活动热力带         | 1.4                |
| 光源     | 唯一光源左上 45°：所有高光在上缘与左缘，阴影紧贴右下 1px                     | 1.3                |
| 材质     | 内容面板**不透明**；只有弹出层 / 待办浮卡用 Acrylic                          | 1.3（Fluent 明文） |
| 色彩     | 单支琥珀；一屏一次色彩事件；语义色独立                                       | 1.1 + 1.2          |
| 字体     | 数字沿用本地 JetBrains Mono（CSP 不许 CDN）；中文不走 mono                   | CSP + 既有约定     |
| 动效     | 一处呼吸 + 数据 tick 闪 50–80ms；其余 120ms `cubic-bezier(.2,0,0,1)`，无回弹 | 1.1 + 项目约定     |

### 与 skill 推荐的偏离（刻意为之，说明理由）

- skill 推荐「深空科技 `#6C63FF` / `#3ECFCF`」和「奢华金融 `#C9A84C`」。前者正是 1.2 里被点名的通用 AI 组合，**不采用**；后者金棕接近我们的琥珀但偏褐、偏奢侈品，与「仪器」不符，**不采用**。
- skill 的 `Space Grotesk` / `Inter` 需 CDN。Tauri 离线 + CSP 禁止外链字体，**保留本地 JetBrains Mono + 系统 sans**；若将来要 display 字体，必须自托管 woff2（与 0.1.x 的字体做法一致）。
- skill 的 hover「上浮 2px + 200ms spring」**不用于表格与卡片**：高频扫描的密集界面里，鼠标划过就在动会干扰读数。改为 hover 只改边框亮度 / 背景亮度，动效只留给一次色彩事件。这符合 skill 自己写的「动效有意义 > 动效存在」。
- skill 的 44px 最小触控尺寸是移动端规范；桌面 dense 仪表盘沿用既有 32px 控件。

### 与概念稿的三处差异（都是有意的）

1. **没有 90 日净值曲线**。后端没有净值时间序列 IPC，不画假数据。位置让给了 90 日**活动热力带**——它从真实交易算出，且同样与底板刻度对齐。想补曲线需新增按日净资产命令。
2. **待办只有两项**，不是概念稿的三项。未对账分录数、未分类交易数没有现成聚合接口；与其编数字，不如只显示能算准的（超预算、久未记账）。这两项将来可以用一个 `dashboard_activity` 命令一次补齐。
3. **玻璃浮卡没有落到生产代码**。`float` 材质已就绪，但首页目前没有需要弹出的临时界面，不为了展示而加一个悬浮层。

### 踩到的三个坑

- **`text-display` 被 `cn()` 吃掉**。tailwind-merge 把不认识的 `text-display` 当作文本颜色类，遇到后面的 `text-foreground` 就把它删掉，主读数静默退回 13px。改成模板字符串拼接类名，别用 `cn()` 包「未知自定义类 + 已知颜色类」。
- **三个 pane 强塞两列会重叠**。原打印样式 `grid-template-columns: 1fr 1fr` 配 `flex-1` 卡片，第三个 pane 与第一个 pane 的第二张卡落在同一位置（实测 270px 重叠）。改成单列文档流，卡片自带 `break-inside: avoid`。两栏省纸，但正确性优先。
- **热力带用 `1fr` 列会变横条**。13 列铺满 560px 时每格宽 40px、高 6px，读起来像条形图。改固定 14px 列 + `justify-content: space-between`，才是 13 组周列。

**验收**：`vitest 107 passed / 12 files`、`tsc --noEmit`、`eslint --max-warnings=0`、`prettier --check`、`vite build`、`gen_error_messages --check (82 keys)` 全绿；产物 CSS 确认含三个 `data-elevation` 选择器、`text-display`、八支深度令牌（浅/深/打印各一份）。另用临时探针 mock `__TAURI_INTERNALS__.invoke` 挂真实 `DashboardPage`，在深色、浅色与 `emulateMedia({media:'print'})` 三态下目视核对；探针与截图均为临时产物，已删除。

## 5. 概念稿

设计阶段做过一版自包含 HTML（`mockups/homepage-v2.html`，深色主版 + 浅色 paper 对照），用于确认「网格底板 + 抬升面板 + 下沉图表槽」在两种模式下都成立。它是**探索工具，不是交付物**：概念里那张玻璃浮卡、90 日净值曲线都因缺少真实数据而没有落地，留着反而会被误当成实现。已删除，落地结果以第 4 节与代码为准。
