# 2026-11-12

## 修复 Windows 上 `make test-backend` 报 0xC0000139 (STATUS_ENTRYPOINT_NOT_FOUND)

- 根因：`tauri-build` 只通过 `rustc-link-arg-bins` 把 Common Controls v6 的 application manifest
  嵌入 bin 目标；`cargo test` 生成的 lib 单元测试 exe 由 Cargo 单独链接，没有任何 manifest，
  Windows 因此加载 System32 的 comctl32.dll v5，缺少 wry 导入的 `TaskDialogIndirect`，
  进程在任何测试运行前就退出。
- 方案（`src-tauri/build.rs`，仅 Windows 分支）：用
  `tauri_build::try_build(Attributes::new().windows_attributes(WindowsAttributes::new_without_app_manifest()))`
  让 tauri-build 只生成 VERSIONINFO/ICON 资源；把 common-controls v6 manifest 写到 OUT_DIR，
  再用 `cargo:rustc-link-arg=/MANIFEST:EMBED` 与 `/MANIFESTINPUT:<path>` 让链接器给所有
  可执行文件（bin / 单元测试 / 集成测试）嵌入同一份 manifest。非 Windows 仍走 `tauri_build::build()`。
- 踩过的坑（避免重复试错）：
  - 无后缀 `rustc-link-arg` 不能指向 tauri 的 `resource.lib`，bin 会重复链接资源报 CVT1100。
  - `rustc-link-arg-tests` 只作用于集成测试目标，覆盖不到 lib 单元测试；且无 test target 时 Cargo 直接报错。
  - `/MANIFESTINPUT` 路径不能自己加引号，rustc 已会为每个链接参数加引号，嵌套引号导致 LNK1327。
- 顺带修复 `src-tauri/src/db/mod.rs::test_debug_format`：Windows 上 `PathBuf` 的 Debug 会转义 `\`，
  断言改为比较 `format!("{:?}", env.path)`（此前被 loader 错误掩盖）。
- 验证：`make test-backend` 370 passed / 0 failed；`cargo build`、`cargo fmt -- --check`、
  `cargo clippy -- -D warnings` 均通过；正式 `glimmerx.exe` 的 ICON / VERSIONINFO / MANIFEST 资源完好。

## 改用官方标准化实现 + 三平台 CI

- 官方 `WindowsAttributes::link_resource_into_all_targets(true)`（tauri-apps/tauri#16320）截至
  tauri-build 2.7.4 仍未发布（docs.rs 最新版的 WindowsAttributes 无该方法）；但底层
  `embed-resource 3.x::compile_for_everything`（winres#42 已合并，tauri-winres 0.3.7 已发布）
  可用，正是官方方案包装的 API。
- `src-tauri/build.rs` 改为：Windows 分支 `tauri_build::try_build(new_without_app_manifest())` +
  写 `common-controls.manifest` 与 `common-controls.rc`（`1 24 "<绝对路径>"`，反斜杠需转义）+
  `embed_resource::compile_for_everything(&rc, NONE).manifest_required()`，由官方 crate 输出
  `cargo:rustc-link-arg` 覆盖所有 target；删除手写的 `/MANIFEST:EMBED`、`/MANIFESTINPUT` 参数。
  `src-tauri/Cargo.toml` 增加 build-dependency `embed-resource = "3"`（Cargo.lock 只多一行引用）。
- `.github/workflows/ci.yml` 的 backend job 改为 ubuntu/windows/macos 三平台矩阵：Linux 装 apt
  依赖、Windows 设 `OPENSSL_SRC_PERL` 指向 Strawberry Perl；fmt 只在 Linux 跑，
  clippy / cargo build / cargo test 三平台都跑；frontend 与 coverage 保持 ubuntu。
- 验证（Windows 本地）：make test-backend 370 passed；cargo build；cargo fmt -- --check；
  cargo clippy --all-targets -- -D warnings 全通过；CI YAML 经 prettier --parser yaml 解析通过。
  非 Windows 分支由 CI 三平台验证（`#[cfg(not(windows))] tauri_build::build()` 保持不变）。
- 升级路径：等 tauri-build 发布 `link_resource_into_all_targets` 后，Windows 块可换成
  `try_build(Attributes::new().windows_attributes(WindowsAttributes::new().link_resource_into_all_targets(true)))`，
  并移除 embed-resource 依赖与自维护的 manifest/.rc。
