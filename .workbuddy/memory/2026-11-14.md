## 修 hover 闪烁（提交 81832ff）

- 症状：鼠标放到图上一直闪，有时图上的内容像消失了。
- 定因方式：临时搭 esbuild + 无头 Chrome 的隔离复现页（`.tmp-repro`，已删），
  直接 import 真实 `src/utils/chartTheme.ts`，把 `rendered`/`highlight` 事件与
  canvas 不透明像素计数埋点，光标定在同一列 ±1px 抖动 90 帧做对照。
- 根因：ECharts 强调态默认 `focus: "series"`，把其余序列压到 **10% 不透明度**。
  双线图上读作"那条线被删了"，且每次指针移动都重触发强调动画 → 两条线交替变暗。
  实测绘制像素 1253 → 1169 并保持；改成 `focus: "none"` 后恒定 1255。
- 次因：tooltip 没有 `confine`（贴边溢出画布，被卡片圆角裁掉一半，像缺了一块）；
  默认 0.4s transform 过渡让盒子追着已过时的光标位置缓动。
- `EChart` 的 ResizeObserver 无条件 `resize()`，改成记录上次尺寸、只在实际变化时执行
  （0 尺寸直接跳过），打印走 `resize(true)` 强制路径。
- 回归测试：`src/utils/chartTheme.test.ts` 锁 `emphasis.focus === "none"`、
  `confine === true`、`transitionDuration === 0`。
- 注意：饼图仍有 `emphasis: { scale: true, scaleSize: 4~5 }`（放大被指扇区），
  这是刻意的手感，未改；若用户反馈饼图也闪，优先怀疑它。

## 修「鼠标放上去线条消失」（未提交，待提交）

- 症状：首页月度收支图，鼠标移上去两条折线整条消失（截图里只剩轴与 tooltip）。
  上一次提交 81832ff 修的是「闪烁 / 另一条线变暗」，**不是**这个。
- 定位路径（关键教训）：**隔离复现不出来**。用 esbuild + 无头 Chrome 搭了个
  只挂 `MonthlyIncomeExpenseChart` 的页面，hover 一切正常——因为它拿到的是
  `useChartColors` 的 **hex 兜底值**；真实页面拿到的是 `oklch()`。
  必须让复现页加载**真实编译后的 CSS**（Vite + 真 `globals.css`）才复现。
- 根因：zrender 的颜色解析器（`zrender/lib/tool/color.js`）只认 hex/rgb/hsl/hsv，
  `parse("oklch(...)")` 返回空 → `lift()` **没有兜底地返回 `undefined`** →
  ECharts 用 `liftColor()` 重建强调态样式（`states.js::createEmphasisDefaultState`）
  时描边变成 `undefined` → 悬停态的 polyline 没有任何 stroke → 线消失。
  附加一层：自定义属性的 computed value 保留未求值 `calc()`
  （`oklch(0.23 calc(0.006 * 1) 250)`），所以连"直接读 token"都不行。
- 解法：`chartColors.ts` 新增 `resolveColor()`——把颜色画进 1×1 canvas 再读像素，
  拿到 canvas 真正会涂的 sRGB 三元组。**`getComputedStyle` 和 `ctx.fillStyle`
  都会把 oklch 原样吐回来，只有像素读回是 rgb。**
- 顺手修的三个真问题（用户贴的控制台）：
  1. `title` 组件没注册 → 环形图中心的总额**从来没画出来过**，
     控制台 `[ECharts] Component title is used but not imported`。
     → `echarts.use([TitleComponent])`。
  2. `grid.containLabel` 在 ECharts 6 属 legacy，每次画图告警。
     → 注册 `LegacyGridContainLabel`（保留调好的旧布局）。
  3. `MarkLineComponent` 全项目没人用 → 从注册表删掉（不进 Tauri 二进制）。
- 验证：真实 CSS 的无头 Chrome 实测——修复前 hover 时彩色像素 8499 → 5446
  （两条线都掉），修复后 8500 → **8691**（提亮的强调态，线还在）；
  环形图中心总额出现；控制台三条告警全清。
  回归测试 `src/utils/chartColors.test.ts` 锁「交给 ECharts 的颜色必须是
  zrender 解析得了的格式」。`vitest 123` / `tsc` / `eslint` / `prettier` 全绿。

## 报表的时间控件：粒度下沉 + 修对比期窗口 + 加对比基期（未提交，待提交）

起因是用户问「报表页面的时间筛选和时间力度是不是有点多余」。分析结论：
**粒度确实多余**——它只影响两张图的 X 轴分桶（`trend.rs` / `account.rs` 的
`strftime`），不影响任何汇总数字，是**坐标轴刻度**却做成了报表级筛选；
且与范围构成 7×4=28 种组合，8 种只切出 1 个桶（图表等于一根柱子，读起来像
"这个月没记账"）、5 种切出 60+ 个桶（挤成一团），后端**没有点数上限**。
业界（GA4 / QuickBooks / Excel / Actual Budget）都没有"粒度"控件，
第二个时间控件一律是**对比基期**。

三件事：

1. **对比期窗口是错的（真 bug）**：`common.rs::get_prev_period_bounds` 对滚动
   预设取 `last_n_months_bounds(2n)`，而那函数的语义是"N 个月前的 1 号 → 今天"，
   结束日从没往前挪 → 对比期比本期长一倍**且包住本期**。
   实测（2026-11-14）：近3月 107 天 vs 200 天、近6月 200 天 vs 386 天、
   近12月 386 天 vs **758 天（两年）**。于是"收入环比 −45%"是窗口长度的算术，
   不是经营的坏消息。改为：自然月/自然年按自然邻期，其余（滚动预设 + 自定义）
   取"紧邻的等长窗口"；补 3 条 Rust 回归测试锁住"等长且不重叠"。
2. **粒度下沉到图上**：新增 `utils/reportGranularity.ts`——刻度由跨度推导
   （≤45 天按日 / ≤120 天按周 / 更长按月），只提供"这个区间画得出来"的刻度
   （点数 6..120），无效选择自动夹紧；控件 `ChartScaleSelect` 长在图表面板
   的 action 槽位（只有一个可选刻度时不出现），筛选条里的粒度下拉删掉。
   URL 的 `g` 改为**只记录用户显式覆盖**，没有覆盖时由区间推导。
3. **加对比基期控件**：新增 `CompareMode`（较上期 / 较去年同期 / 不对比），
   后端 `CompareMode` 进 `ReportFilter`（`#[serde(default)]`），
   `get_comparison_bounds` 统一算对比窗口；前端 URL 参数 `c`，
   控件放在现金流报表的 ReportFrame toolbar（只有它做对比）。
   选"不对比"时对比表与变化率整块不出现。
   "去年同期"此前产品里根本看不了（近 12 个月的对比期是"前 12 个月"）。

验证：`make check` 全绿（含 cargo clippy/fmt），Rust 414 passed、

`useReportQuery.test.tsx` +4 条）。文档 `docs/design/24-reports.md` 同步重写

## AI 记账 P3 MCP 服务完成（未提交）
