- **预算必须按分录分摊**：`list_budget_statuses` 的日期条件要放进
  `SUM(CASE WHEN t.date >= ?1 ... THEN p.amount ELSE 0 END)`，不能写进
  `LEFT JOIN ... ON`（会被后续 join 覆盖）也不能进 WHERE（会把无花费的预算过滤掉）。
- **表单分类选择器的位置是错的**：原来顶部一个交易级"分类"下拉，与分录里的账户
  下拉重复，用户选了不一致的值数据就自相矛盾。v3 删掉它，每行分录一个合并选择器：
  资产/负债归"账户"组，损益归"分类"组（用分类图标+名字显示），落库永远只有账户 id。
- **详情页/卡片显示分类名**：`PostingDetail` 带 `categoryId/categoryName`；
  列表 `categoryNames: Vec<String>`（>2 个显示"等 N 项"）。

踩坑：

- 报表夹具原本"独立建 P&L 账户 + 另建同名分类"，切换口径后分类金额全是 0。
  所有夹具改成 `account_id_for_category(cat_id)` 拿镜像账户。
- `make_transaction_with_category` 的 `category_id` 参数成了死参数，
  批量改名时把已有 `make_transaction` 一起改重名，需手工合并。
- `clippy --all-targets` 比 `make check` 更严（后者不带 `--all-targets`），
  批 B 写下的 `&[x.clone()]` 被判为单元素切片应改用 `std::slice::from_ref`。
  CI 跑的是 `--all-targets`，所以本地要按 CI 的口径验。

## 建议级项：行为 bug / 安全收敛 / 报表性能

修完 Critical 与必须改后，把剩下的建议级项也做完（用户三类全选）。

**行为 bug**

- Top 支出是分录级统计，`transaction_id` 不唯一 → 后端补 `posting_id`，React key 改用它。
- 列表项新增 `flow_amount`（只汇总资产/负债侧）：`display_amount` 是借方合计恒正，
  拿它判断收/支是死分支，支出也被染成绿色。支出负、收入正、自有账户互转 0。
- 全局快捷键插件按下与抬起都触发 → 必须 `event.state === "Pressed"` 过滤，
  否则快速记账窗"开了又关"。
- 快速记账切模式要无条件清 `categoryId`：下拉已按模式过滤，残值不可见却会被提交。
- 详情页每次渲染重建 `transaction` 对象 → 表单初始化 effect 反复跑，**正在填的内容被清空**。
  改 `useMemo`。判断"对象是否需要 memo"的标准是「它是否喂给了 effect 的依赖」。
- `TransactionDetail.categoryId/categoryName`、`UpdateTransactionInput.categoryId` 是 v3 残留，
  后端已不返回，对应卡片永远不渲染，一并删除。

**安全**

- `capabilities/default.json` 去掉 `fs:default` / `opener:default`（前端只用 dialog 插件）。
- `lockSession` 从 fail-open 改为返回 `boolean`：只在解锁态调 `dbLock`（已锁时调必失败），
  失败重试一次，仍失败则 UI 照旧清空但错误冒泡，侧栏/改密用 `common.lockFailed` 提示。
- `db_check_exists` 只接受 `*.db` 且 `is_file()`，否则锁屏下就是个文件系统探测器。

**性能**

- `db_lock` 关库前跑 `PRAGMA optimize`（best-effort，失败不阻断锁定）。
- 两月对比把日期范围下推到 `WHERE`（`MIN(?1,?3)`/`MAX(?2,?4)`，ISO 字符串可字典序比较）；
  结果等价，因为越界的行对两个月都贡献 0、本来就被 `HAVING` 丢掉。
- 余额趋势用 `MAX(p.rowid)` 找"本期最后一条"但窗口按日期排序：补录旧日期交易时，
  取到的是插入最晚那条 → 期末少算。改 `ROW_NUMBER() OVER (ORDER BY t.date, p.rowid)`。
  这类 bug 只有"插入顺序 ≠ 日期顺序"时才现形，必须有专门测试。
- 账户明细 `total_count` 从 `COUNT(DISTINCT t.id)` 改 `COUNT(*)` 对齐分录级行粒度。
